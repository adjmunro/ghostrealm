---
name: build
description: Use before running cargo, mise or zig in this repo, or when target/ needs cleaning.
---

- `cargo` lives in `~/.cargo/bin`, which the agent shell's `PATH` lacks: `export PATH="$HOME/.cargo/bin:$PATH"` first. There is no `timeout` binary.
- Zig is pinned in `mise.toml` and is required to build `libghostty-vt-sys` (it compiles Ghostty from source). Run cargo from the repo root so `mise` activates Zig, or prefix `mise exec --`. The scratchpad has no `mise.toml`, so Zig is not on `PATH` there: export it explicitly when building outside the repo.
- Export `GHOSTREALM_NO_WEB=1` for every cargo command unless the task touches web (the web-host skill), including throwaway `CARGO_TARGET_DIR` builds and scratchpad workspace copies (the non-macOS compile check). Without it the app's build script builds and bundles the CEF web host, which in a fresh target dir downloads CEF (~250 MB) and takes minutes. Toggling it reruns the build script and recompiles the app crate once.
- Build scripts can't see a command-line `--offline` or `--frozen`: offline builds set `CARGO_NET_OFFLINE=true` (or `GHOSTREALM_NO_WEB=1`). Nor a command-line `--target-dir`: the web host is then skipped; set `CARGO_TARGET_DIR` (absolute) instead.
- `target/` grows without bound (Cargo keeps superseded hashed copies). Each run of the app's build script (`crates/app/build/prune.rs`) starts clean-stale detached, at most hourly, to prune `target/` once the build releases its locks (log: `target/clean-stale-after-build.log`); not with `CARGO_TARGET_DIR`, nor with `GHOSTREALM_NO_PRUNE=1`. `mise run clean-stale` frees them, in `target/` and in `target/web-host` (the web host's own target dir); `-- --unused-days N` also removes units none of whose files was modified in N days, in use or not (rebuilt on the next build; build-script runs, which can hold downloads, are kept). It skips a target dir while a build holds its locks, or when its lock files can't be opened or created (`can't lock …; skipped`), so it is safe to run any time. It refuses (exit 2) when `CARGO_TARGET_DIR` is set without `--target-dir`.
- `mise run clean-all` also runs that cleanup on every other worktree's `target/`. On macOS it also empties target dirs of agent worktrees (`.claude/worktrees/*`), scratchpads and ghostrealm target dirs in the system temp dir once idle (`--idle-hours`, default 2) and no running program lives in them, keeping `CACHEDIR.TAG`, lock files and dirs with other locks; and it removes leftover test and web-host temp dirs. On other systems it empties and removes none of these. An agent worktree awaiting review or fixes loses its `target/` this way, so pass `-- --except <worktree>/target` (repeatable) for each whose `target/` exists (a missing `--except` dir is an error and nothing is cleaned), or leave clean-all to the director.
- Add `-- --dry-run` to either to list what would go; a dry run removes and creates nothing in the dirs it would clean (the mise tasks still build `target/clean-stale`).
- Never share a `CARGO_TARGET_DIR` between checkouts: `target/debug/ghostrealm` and the web bundle beside it are overwritten by whichever checkout built last, and the app finds the web host next to its own executable.
- Only `aarch64-apple-darwin` is installed, so non-macOS `cfg` code is never compiled by default. When a change touches it, compile-check it on a copy in the scratchpad: for `scripts/*.rs`, the file (`rustc --edition 2021 --test`); for crate code, a copy of the whole workspace in the scratchpad, built with `CARGO_INCREMENTAL=0`, since crates inherit workspace settings and depend on each other's `cfg` code (a role that can write may use a worktree instead, built with its own `CARGO_TARGET_DIR` and `CARGO_INCREMENTAL=0`). In the copy, swap `target_os` in every `.rs` both ways through a placeholder (`"macos"` → `"@"`, `"linux"` → `"macos"`, `"@"` → `"linux"`) so `cfg(target_os = "linux")` and `any(...)` code swap too. This catches `cfg` and import slips, not Linux-only APIs.
- For a throwaway target dir, set `CARGO_INCREMENTAL=0`: incremental caches only pay off on rebuilds and add gigabytes.
